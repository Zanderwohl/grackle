# Map blueprints as a feature list

The map editor is being reworked so that a map works the way a prop already
does: **the file is the feature list**, undo is a separate axis that lives in
memory, and the rollback bar is a way of looking at the list rather than part
of it. Tick items off as they land; the checklist is the source of truth.

No backward compatibility: existing `.gmb` SQLite files are not read. The
shipped template is regenerated by `cargo run --bin new_map_template`.

## Where it started (October 2026)

`FeatureTimeline` held three things that were tangled together:

- **The feature list** — `features` + `feature_order` — with a `rollback_bar`
  count that `undo()`/`redo()` moved (the Timeline panel's Backward/Forward).
- **An action history** — `actions` of per-feature `FeatureDelta`
  before/after `FeatureSnapshot`s, with coalescing — which Ctrl+Z drove and
  the History panel listed.
- **Persistence of both** in a SQLite blueprint with a numbered migration
  chain and a per-feature-type `FeatureData` enum, registered in seven places.

And `apply_feature` **deleted every feature past the bar** when something was
added while rolled back.

## Decisions

- **The blueprint is flat text**: pretty **RON** written straight from the
  features' own serde (`typetag`), the same serde `map_sync` already sends.
  RON (the user's call, over JSON) writes an `f32` as its shortest decimal
  (`0.05`, not `0.05000000074505806`), has `None`/`Some`, reads as Rust, and is
  what Bevy writes scenes in. Extension stays `.gmb`.
- **Undo is whole-map snapshots in memory**, like the prop editor: not saved,
  lost on close. A snapshot is each feature's serialized form in order, so
  restoring one rebuilds **only the features that differ** — an undo does not
  respawn every room.
- **Checkpoints, not instrumentation.** Rather than every tool calling
  `begin_edit`/`end_edit`, the map is checkpointed whenever it is idle — no
  mouse button held and egui not using the pointer or keyboard — and differs
  from the last checkpoint. A drag is one step because the button is held for
  all of it; typing a name is one step because the field has the keyboard.
- **Rollback is view state**: the id of the last feature shown, not a count.
  Not saved, not sent to clients, not undone; adding a feature while rolled
  back inserts at the bar. Entering Play rolls to the end — a round is played
  on the whole map.
- **One History panel**: the Timeline panel becomes **History** — the feature
  list with a draggable rollback bar — and the old action-list History panel
  goes.
- **Revert is one undo step** in the map editor too, now that history is in
  memory, and the map gets a real dirty flag (differs from what was last
  saved or loaded).

## Checklist

### Stage 1 — text format

- [x] `save.rs` replaced: `save`/`load` of `{ metadata, next_id, features }`
      as pretty RON, written through a `.bak` as before.
- [x] `MapMetadata` on disk as `{ authors, game_mode }`; its SQLite rows,
      CSV helpers and the schema-version row in the metadata panel go.
- [x] `new_map_template` writes the new format; template regenerated.
- [x] Template test (room, light, spawn with headroom) ported; one round-trip
      test over a map holding every feature type replaces the per-type ones.
- [x] `rusqlite` removed from `Cargo.toml`; `SCHEMA_VERSION` and migrations
      gone. `map_sync` no longer sends the rollback bar (pulled forward from
      stage 3: `from_parts` no longer takes one).

### Stage 2 — undo as snapshots

- [x] `MapState` snapshot + undo/redo stacks + `checkpoint_when_idle`.
      `sync_entities` bypasses change detection, so entity bookkeeping does
      not read as an edit every frame.
- [x] Restore rebuilds only features whose serialized form changed (and their
      descendants), and re-resolves references at once.
- [x] `adopt` and loading reset history (no history crosses the wire).
- [x] `action.rs`, `FeatureData`, `FeatureSnapshot`, `FeatureDelta`,
      `snapshot`/`apply_snapshot`, `scalar_fields`/`set_scalar_field`,
      `point_ref_slots`, `create_object_from_type_key`, `begin_edit`/`end_edit`
      removed. The old action-list History panel goes with them.
- [x] Dirty flag; asterisk in the map editor's menu bar.

### Stage 3 — rollback as a view

- [x] `rollback: Option<FeatureId>`; `active_features`/`shown_len` evaluate to
      it; `sync_entities` stands up only what is above it.
- [x] Adding while rolled back inserts at the bar.
- [x] One **History** panel (the Timeline tab, renamed) with a draggable bar
      and "Roll back to here" / "Roll to end"; Backward/Forward buttons and the
      old History panel removed.
- [x] Entering Play rolls to the end — on the Editor→Play transition, with
      `sync_entities` after it, so the bake in `OnEnter(Play)` sees every room;
      `map_sync` stops sending the bar (done in stage 1).

### Stage 4 — wiring and docs

- [x] Edit menu: Undo/Redo on the new history; Revert as one undo step,
      enabled only when dirty (pulled forward into stage 2).
- [x] CLAUDE.md: Save format, the feature model's registration list, undo and
      the History panel, the RosterTeam note, targeting wasm, and the shipped
      template. `RosterTeam::index`/`from_index`, which only existed for the
      scalar-fields table, removed.

### Noticed along the way

- [x] ~~Prop editor: `end_gesture` closes mid-way through a viewport gizmo
      drag.~~ Checked, and not a bug: the first frame pushes the state from
      *before* the drag, and `undo` pushes whatever is current onto redo, so
      Ctrl+Z goes back to before the drag and redo comes back to its end.

### Where wasm stands afterward

`cargo check --lib --target wasm32-unknown-unknown` compiles every dependency
and stops on seven errors in Grackle's own code: the UDP transport in
`net_transport.rs`, and the `rfd` file dialogs (`FileHandle::path`,
`pick_folder`) in the three editors.
